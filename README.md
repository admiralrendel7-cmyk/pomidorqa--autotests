# PomidorQA — автотесты

Автотесты для сервиса [PomidorQA](https://aiqa.su/pomidorqa), выполненные в рамках марафона «Автоматизация на Playwright + TypeScript».

PomidorQA — сервис коротких встреч для QA-сообщества: указываешь навыки, выбираешь свободный слот, бронируешь 25 минут с коллегой.

## О проекте

Проект содержит автотесты на трёх уровнях:

- **Unit** — проверка отдельных функций без браузера и сети.
- **API** — проверка HTTP-сценариев через локальный mock-сервер.
- **E2E** — проверка пользовательских сценариев в браузере на живом сервисе PomidorQA.

E2E построены на Page Object: сценарий живёт в `tests/e2e/`, пользователь и вход — в `tests/helpers/`, локаторы и действия экрана — в `tests/pages/`.

## Стек

- TypeScript
- Playwright
- ESLint
- GitHub Actions

## Установка

Нужен Node.js.

```bash
npm ci
npx playwright install chromium
```

## Запуск

```bash
npm test            # все тесты
npm run test:unit   # Unit — без сети и без браузера
npm run test:api    # API — HTTP-запросы к локальному мок-серверу
npm run test:e2e    # E2E — браузер на https://aiqa.su/pomidorqa
npm run lint        # ESLint
npm run report      # HTML-отчёт последнего прогона
```

По умолчанию E2E идут на продакшен (`https://aiqa.su`). Для локального стенда:

```bash
POMIDORQA_BASE_URL=http://localhost:3000 npx playwright test --project=e2e
```

## Что покрыто

### Unit

- пересечение временных слотов;
- отображение времени в разных часовых поясах;
- валидация пароля при регистрации.

### API

- регистрация нового пользователя;
- повторная регистрация с существующим email;
- бронирование свободного слота;
- попытка забронировать собственный слот;
- бронирование слота в прошлом;
- бронирование несуществующего слота;
- повторное бронирование занятого слота;
- конкурентная попытка двух пользователей забронировать один слот.

### E2E

- заполнение и сохранение данных профиля (имя, часовой пояс, telegram, «о себе»);
- добавление навыка «могу помочь» и негативные проверки навыков;
- поиск участника в каталоге по навыку;
- хост не видит свою карточку в выдаче;
- бронирование слота гостем;
- отмена брони — карточка уходит в «Прошедшие» у гостя и хоста;
- вход с неверными данными: одинаковая ошибка без уточнения причины.

Arrange каталога идёт через тестовое API (`POST /api/pomidorqa/test/accounts`), UI проверяет поиск и выдачу. После сценария аккаунты удаляются.

## Структура

```
src/pyramid/          чистые функции (unit) и локальный мок-сервер (api)
tests/unit/           пересечение слотов, часовые пояса, пароль
tests/api/            регистрация, бронирование, гонка за слот
tests/e2e/            профиль, каталог, бронь, отмена, ошибка входа
tests/helpers/        makeUser, регистрация UI/API, очистка
tests/pages/          ProfilePage, BookingPage
.github/workflows/    Playwright CI
```

## CI

[GitHub Actions](https://github.com/admiralrendel7-cmyk/pomidorqa--autotests/actions) на каждый `push` и `pull_request` в `main`:

1. установка зависимостей;
2. ESLint;
3. Playwright (unit, API, E2E);
4. HTML-отчёт как artifact.
