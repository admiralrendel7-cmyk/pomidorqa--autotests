# PomidorQA — автотесты

Автотесты для сервиса [PomidorQA](https://aiqa.su/pomidorqa), выполненные в рамках марафона «Автоматизация на Playwright + TypeScript».

PomidorQA — сервис коротких встреч для QA-сообщества: указываешь навыки, выбираешь свободный слот, бронируешь 25 минут с коллегой.

Источник требований — [`requirements.md`](requirements.md).

## О проекте

Проект содержит автотесты на трёх уровнях:

- **Unit** — проверка отдельных функций без браузера и сети.
- **API** — проверка HTTP-сценариев через локальный mock-сервер.
- **E2E** — проверка пользовательских сценариев в браузере на живом сервисе PomidorQA.

E2E построены на Page Object: сценарий живёт в `tests/e2e/`, пользователь и вход — в `tests/helpers/`, локаторы и действия экрана — в `tests/pages/`.

## Ключевые результаты

Срез: полный прогон `npx playwright test --workers=1`, `TZ=UTC`, стенд `https://aiqa.su/pomidorqa`.

Покрытие считается по **50 атомарным правилам** из разделов 3–12 [`requirements.md`](requirements.md). Это requirement coverage, а не code coverage продукта: исходников PomidorQA в репозитории нет.

| Метрика | Значение |
| --- | ---: |
| Требований MVP (разделы 3–12) | 50 |
| Полнота аудита | **50 / 50 (100%)** |
| `automated` | **45 / 50 (90%)** |
| `partial` | 2 / 50 (4%) |
| `known defect` | 1 / 50 (2%) |
| `out of scope` | 2 / 50 (4%) |
| Unit | 18 |
| API | 16 |
| E2E | 37 |
| Всего автоматизированных проверок | **71** |

Автоматизированное покрытие требований и количество тестов — разные метрики. У всех 50 правил есть статус; 45 подтверждаются автотестами на подходящем уровне (live E2E, live test API или явно смоделированный mock API).

`partial`: R7.2 — слот в прошлом блокируется формой, прямой server-side обход live UI недоступен; R10.4 — гонка доказана на mock API, live e2e-гонка не гоняется, чтобы не перегружать общий стенд.

### Покрытие по разделам requirements.md

| Раздел | Статус | Что доказано автотестами |
| --- | --- | --- |
| 3. Роли | `automated` | гость видит каталог и слот, но не бронирует и не открывает приватные страницы; участник правит профиль, слоты, бронирует, отменяет, видит встречи |
| 4. Регистрация и вход | `automated` | обязательные поля, пароль ≥ 8, имя и `Europe/Moscow` после регистрации, повторный email (live API), одинаковая ошибка входа, сессия и logout |
| 5. Профиль | `automated` | имя (в т.ч. обязательность), Telegram, пояс, «о себе»; время слота в поясе владельца |
| 6. Навыки | `automated` | `can_help` / `want_to_learn`, пустой навык, удаление, запрет дубля, один текст в двух типах |
| 7. Слоты | `automated` + `partial` | создание, удаление free, booked без «Удалить»; прошлое — форма + mock API |
| 8. Каталог | `automated` + дефект | поиск, self-exclusion, без слота нет в выдаче, неизвестный навык — пусто |
| 9. Страница участника | `automated` | имя, «о себе», оба типа навыков, свободный слот; после брони слот исчезает |
| 10. Бронирование | `automated` | happy path, свой слот, закрытие диалога без брони; прошлое/занятый/гонка — mock API |
| 11. Отмена | `automated` | отмена гостем и хостом, правило 2 часов, повторная бронь другим гостем |
| 12. Мои встречи | `automated` | «Ближайшие» у обоих; после отмены — «Прошедшие», без кнопки «Отменить» |
| 13. Критерии приёмки | `automated` | основной путь 1–6 и негативы закрыты; живая гонка остаётся на mock API |

Единственный известный продуктовый дефект — **R8.3**: каталог находит участника по навыку «хочу разобрать», хотя требование ограничивает поиск разделом «могу помочь». Проверка написана по требованию и помечена `test.fail()`, поэтому дефект виден и не маскируется зелёным результатом.

## Что покрыто

| Область | Проверяемые риски |
| --- | --- |
| Вход | обязательные поля, короткий пароль, одинаковая ошибка входа, сессия, logout, защита приватных страниц |
| Профиль | имя, Telegram, часовой пояс, «о себе»; дефолт `Europe/Moscow`; пустое имя не сохраняется |
| Навыки | `can_help` / `want_to_learn`, пустой навык, удаление, уникальность, один текст в двух типах |
| Слоты | пересечение (unit), пояса из спецификации (unit), создание, удаление free, booked не удаляется, прошлое не создаётся |
| Каталог | поиск, self-exclusion, без слота нет в выдаче, неизвестный навык — пусто |
| Бронирование | happy path, гость без аккаунта, свой слот, закрытие диалога; mock API — прошлое, занятый слот, гонка |
| Отмена | гость и хост, окно 2 часов, слот снова свободен для другого |
| Встречи | «Ближайшие» у обоих; «Прошедшие» после отмены, без повторной отмены |

### Unit

- пересечение временных слотов;
- отображение времени во всех поясах из `requirements.md`;
- валидация пароля и обязательных полей регистрации.

### API

- регистрация, повторный email, пустое имя, короткий пароль (mock + live test API);
- бронирование свободного слота, свой слот, прошлое, несуществующий, занятый, гонка;
- удаление free-слота, запрет удаления booked, отмена брони и повторный захват слота.

### E2E

- регистрация: обязательные поля, имя и `Europe/Moscow`, сессия и logout;
- профиль: поля, обязательность имени, навыки обоих типов, удаление, дубль;
- каталог: поиск, self-exclusion, без слота, неизвестный навык, публичная карточка;
- слоты: прошлое, удаление free, booked без «Удалить», пояс владельца;
- бронь: happy path, гость без входа, свой слот, закрытие диалога, слот исчезает;
- отмена гостем и хостом, правило 2 часов, повторная бронь, нельзя отменить из прошедших;
- вход с неверными данными: одинаковая ошибка без уточнения причины.

Хост и гость в каталожных и части броневых сценариев создаются через тестовое API. После теста аккаунты удаляются.


## Установка

Нужен Node.js.

```bash
npm ci
npx playwright install chromium
```

## Запуск

```bash
npm test            # все тесты
npm run test:unit   # Unit — без сети и без браузера
npm run test:api    # API — HTTP-запросы к локальному мок-серверу
npm run test:e2e    # E2E — браузер на https://aiqa.su/pomidorqa
npm run lint        # ESLint
npm run report      # HTML-отчёт последнего прогона
```

По умолчанию E2E идут на продакшен (`https://aiqa.su`). Для локального стенда:

```bash
POMIDORQA_BASE_URL=http://localhost:3000 npx playwright test --project=e2e
```

## CI

[GitHub Actions](https://github.com/admiralrendel7-cmyk/pomidorqa--autotests/actions) на каждый `push` и `pull_request` в `main`:

1. установка зависимостей;
2. ESLint;
3. Playwright (unit, API, E2E);
4. HTML-отчёт как artifact.
